# Runbook — credential & key compromise (identity secrets)

Every identity secret lives in Secrets Manager (`karen/<env>/api/*`), never in code or logs.
Rotation keeps the OLD value valid only as long as needed, then removes it.

| Secret                                          | Exposure impact                                               | Rotate                                                                                                                                                                                             | Side effects                                                                                           |
| ----------------------------------------------- | ------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------ |
| `ACCESS_TOKEN_SIGNING_KEYS` (ES256 JWKs)        | Forged mobile access tokens (still need a live session row)   | Add new JWK (new `kid`), set `ACCESS_TOKEN_CURRENT_KID`, deploy; after 10 min (one access TTL) remove the old kid and deploy                                                                       | None for users. If the key itself leaked: remove the old kid IMMEDIATELY (mobile clients refresh once) |
| `PASSWORD_PEPPERS`                              | Offline cracking of leaked hashes becomes possible            | Add new id, set `PASSWORD_PEPPER_CURRENT_ID`; hashes upgrade on next sign-in; keep old id until no hash references it (`SELECT pepper_id, count(*) FROM identity.password_credentials GROUP BY 1`) | If hashes AND pepper leaked: force resets (lock accounts → recovery e-mail)                            |
| `OTP_HMAC_KEY`                                  | Codes verifiable offline from a DB leak; Redis key derivation | Replace; open codes become invalid (users press "resend"); rate-limit counters reset                                                                                                               | Short burst of "code invalid" — expected                                                               |
| `CONSENT_RECEIPT_KEY`                           | Receipts could be forged                                      | Replace; existing receipts then fail MAC verification → record the rotation time and key-id in the incident; re-anchor verification per key id (known limitation R8)                               | Verification endpoint reports invalid for old receipts until key-id-aware verification ships           |
| `INTERNAL_SERVICE_HMAC_SECRET`                  | Forged worker → API calls (data-rights steps)                 | Rotate on API and temporal-worker together (brief 401s; Temporal retries)                                                                                                                          | Activities retry automatically                                                                         |
| `BREVO_SMTP_KEY`                                | Mail sent as KAREN                                            | Revoke in Brevo, create new key, update secret, deploy                                                                                                                                             | Mail pauses briefly; users can resend                                                                  |
| `STAFF_DATABASE_URL` / `DATABASE_URL` passwords | DB access as that role                                        | Rotate DB role password, update secret, deploy                                                                                                                                                     | Short reconnect                                                                                        |

**Mass session revocation** (suspected session-store or signing compromise):
`UPDATE identity.sessions SET revoked_at = now(), revoke_reason = 'logout_all' WHERE revoked_at IS NULL;`
run by an operator in a recorded change — every client must sign in again. Audit the change.
