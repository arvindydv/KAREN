  (T-…) refer to `PHASE_03_TEST_STRATEGY.md`. Security checks (SR-…) refer to
  `PHASE_03_SECURITY_RELIABILITY_CHECKLIST.md`.

Rules that apply to every milestone (not repeated below):

1. One PR per milestone half, branch `phase-03/mNN-<topic>`, into a **protected** `main` (D13).
2. `MEMORY_FEATURE_ENABLED=false` default everywhere; the suites enable it only in local/test.
3. Before merge: `pnpm verify`; `pnpm test:integration` if DB/Redis/Temporal behaviour changed;
   `pnpm verify:py` if Python changed; `pnpm contracts:check` if contracts changed (commit the
   regenerated files). CI green on every required check. No skipped or disabled tests.
4. No new dependency without an ADR-level reason and the 7-day release-age rule (ADR-0010).
5. No memory content in logs, metrics labels, audit metadata, Redis or Temporal history.
6. Anything not proven in the PR is labelled **NOT VERIFIED** in the PR description.
7. The milestone is **complete** only when its exit conditions hold **and** the owner has merged
   it. A green CI run alone does not complete a milestone.
