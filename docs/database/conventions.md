# Database conventions

- **Authority:** PostgreSQL is the source of truth for business state. Redis is ephemeral only.
- **Ownership:** one Postgres schema per owning module (`identity`, `consent`, `audit`, `platform`, …). Only the owner writes; others call its service/API or consume events.
- **IDs:** UUID primary keys generated by the database (`gen_random_uuid()`). External identifiers are separate columns with unique constraints.
- **Naming:** snake_case tables/columns via `@@map`/`@map`; Prisma models in PascalCase.
- **Time:** `timestamptz(3)`; `created_at` on every row, `updated_at` on mutable rows; display in the user's timezone.
- **Concurrency:** mutable aggregates carry `version int` and are updated with compare-and-set.
- **Ownership columns:** every user-owned row has `user_id` and an index **leading** on it (`(user_id, …)`). Never trust a client-supplied user ID; always derive from the principal.
- **Money:** integer minor units + ISO currency code.
- **Sensitive data:** no tokens, OTPs, raw prompts or unnecessary PII in JSON blobs or audit metadata; encrypt connector tokens (envelope encryption) when they arrive.
- **Transactions:** `PrismaService.withTransaction` (ReadCommitted default, 10 s timeout). Write outbox events in the same transaction as the state change.
- **Migrations:** `prisma migrate dev` locally; reviewed SQL committed; expand/contract for breaking changes; `prisma migrate deploy` in deployment is a separate, explicit, approved step (never automatic for production). CI applies all migrations from scratch and checks schema↔migration drift (`db:migrate:diff`).
- **Extensions** are created in SQL migrations (`vector`), not via Prisma preview features.

## Local procedures

```bash
pnpm db:migrate          # create/apply migrations in dev (prompts for a name)
pnpm db:migrate:status
pnpm db:seed             # synthetic users only; refuses outside local/test
pnpm db:reset            # DESTROYS local data: drops, re-applies migrations, re-seeds
pnpm --filter @karen/api db:migrate:diff   # drift check (needs SHADOW_DATABASE_URL)
```

Full local wipe including volumes: `docker compose down -v && pnpm infra:up && pnpm db:migrate:deploy`.
